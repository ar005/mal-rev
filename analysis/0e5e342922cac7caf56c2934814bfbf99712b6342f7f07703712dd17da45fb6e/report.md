### New Findings & Enhanced Behaviors

#### 1. Expansion of Target Ecosystems (Steam & Telegram)
The new disassembly reveals a heavy focus on gaming and communication infrastructure:
*   **Steam:** Function `fcn.00409fb0` targets the Steam platform by querying the Windows Registry (`Software\Valve\Steam`) to find installation paths. It then crawls these directories looking for `.vdf` files (e.g., `config.vdf`, `loginusers.vdf`). These files contain session information and login details for Valve's ecosystem.
*   **Telegram:** Function `fcn.0040a400` contains specific logic for **Telegram "tdata" collection**. This is a high-value target for attackers, as stealing the `tdata` folder allows them to clone the user’s session and read messages without needing the original password or 2FA.

#### 2. Deep Cryptocurrency Wallet Mining
While earlier chunks showed general wallet interest, chunk 3 reveals specific logic:
*   **Cryptocurrency Specifics:** Function `fcn.0040ef90` performs a "Deep Search" for files with extensions such as `.wallet`, `.key`, and `.kdbx`. These are common formats for hardware wallets or offline wallet storage.
*   **Signature Matching:** Function `fcn.0040aea0` specifically looks for strings like `json_wallet`, `bitcoin_wallet.dat`, and even checks files for internal headers like `"salt"`, `"iv"`, and `"cipher"`. This confirms the malware is looking for the "root" of crypto assets, not just a browser extension.

#### 3. Advanced Decryption & Decoding Logic
The malware employs multiple methods to bypass local security:
*   **System API Decryption:** `fcn.00403540` acts as a wrapper for `CryptUnprotectData`. This is the standard Windows method for decrypting data that was encrypted using the OS's Master Key (common in "Credential Manager" style storage). 
*   **BCrypt Implementation:** For higher-level security, it also uses the **BCrypt API** to generate symmetric keys and decrypt data. This indicates a sophisticated design capable of handling various levels of encryption used by different applications.
*   **Base64/Data Transformation:** `fcn.00406a20` processes decrypted buffers to ensure they are formatted correctly for exfiltration (handling Base64-style padding and conversion), ensuring the "raw" data is converted into a clean string before being sent over the network.

#### 4. Active Memory Scanning & Injection
Function `fcn.00403b10` shows how the malware identifies targets:
*   **Process Scrutiny:** It iterates through running processes looking for `chrome.exe` and `msedge.2e.exe`.
*   **Memory Inspection:** It doesn't just check if a browser is open; it reads the process memory to search for strings like `"https"` and `"network.ssl"`. This confirms it looks for specific processes that are actively handling secure web traffic, likely to snag active session cookies or live "in-memory" tokens.
